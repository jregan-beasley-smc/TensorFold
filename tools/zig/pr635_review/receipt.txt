Reproduce from the repository root with Zig 0.17.0

    zig build test-cuda-host -j2 --summary all
    zig test -lc --dep graph_cache -Mroot=tools/zig/pr635_review/acceptance.zig -Mgraph_cache=zig/src/cuda/graph_cache.zig
    zig build-exe -lc -O Debug --dep cuda -Mroot=tools/zig/pr635_review/cuda_gate.zig -Mcuda=zig/src/cuda/root.zig -femit-bin=/tmp/pr635-device-probe
    /tmp/pr635-device-probe

Run the device probe only on an available CUDA GPU, using the machine's normal lock and admission guard. The receipt's run used a 30-second process deadline and a 16 GiB MemAvailable floor. The standalone harness does not provide that external supervision or service-state auditing. It retains/releases its own process context and never resets the device.
For the before control, use an isolated checkout at the base SHA and point -Mgraph_cache or -Mcuda there while keeping the same test sources.
VMM can report unsupported or skipped_granularity on other devices; those outcomes do not qualify that path. It reported passed on this Spark.

Source identity
The device harness is the tested source with only zig fmt whitespace changes. results.json records the tested and publication hashes. The acceptance source has only single-line comment edits for the repository style. The original failure/control and combined-fix runs used the same unformatted device harness. The fixes themselves have no publication-time source changes.

Scope and distributed cost
When Agree is installed, a cache hit now takes three agreement callbacks instead of zero; a successful capture miss takes six instead of two. These keep rank decisions aligned, but their real collective and host-synchronisation cost is unmeasured. The underlying transport determines that cost. With Agree absent, the checks are local.
The paired-thread tests prove the tested host-policy paths; actual two-GPU/NCCL capture, transport failures, model serving, end-to-end performance and model quality remain untested here. The exact failing VMM driver-call return code was not instrumented. This work does not establish a cause for unrelated CUDA719 reports.
